# library.author — Design Specification

## Purpose
Represents a person who writes or contributes to books. This model serves as the foundational entity for author attribution in the library system.

## Public API (Contract)
These elements form the stable interface that other modules can depend on:

### Fields (Public Interface)
- **id** (int): Primary key
- **name** (char, required): Full name of the author
- **display_name** (computed): Formatted name for UI display
- **partner_id** (many2one res.partner, optional): Link to contact information

### Methods (Public Interface)  
- **get_books(self, domain=None)** → recordset(library.book): Returns books authored by this person
- **as_dict(self, fields=None)** → dict: Returns author data as dictionary for API usage
- **search_authors(domain, limit)** -> recordset(library.author)(static): Helper for efficient author searches

## Fields (Detailed Implementation)

### Core Fields
- **name**: Char(required=True, index=True)
  - Help: "Full name of the author"
  - Normalized on create/write (trim spaces, collapse multiple spaces)
- **birth_date**: Date(optional)
  - Help: "Date of birth"
  - Constraint: Cannot be in the future
- **death_date**: Date(optional) 
  - Help: "Date of death"
  - Constraint: Must be >= birth_date if both exist
- **country**: Char(optional)
  - Help: "Country of origin"
- **biography**: Text(optional)
  - Help: "Brief biographical information"

### System Fields
- **partner_id**: Many2one('res.partner', ondelete='set null')
  - Help: "Related contact record for additional information"
- **active**: Boolean(default=True)
  - Help: "Uncheck to archive the author"

| Field        | Type                        | Required | Notes |
|--------------|-----------------------------|----------|-------|
| id           | Integer (PK)                | Yes      | Auto-generated by Odoo |
| name         | Char                        | Yes      | Mandatory, trimmed, normalized |
| book_ids     | Many2many(`library.book`)   | No       | Simple M2M for performance |
| partner_id   | Many2one(`res.partner`)     | No       | Optional link to contact, `ondelete='set null'` |
| birth_date   | Date                        | No       | Must not be in the future |
| death_date   | Date                        | No       | Must be >= `birth_date` |
| is_duplicate | Boolean                     | No       | Flag for deduplication workflows |

## Relations

### Direct Relations
- **book_ids**: Many2many('library.book', 'library_book_author_rel', 'author_id', 'book_id')
  - Inverse field of library.book.author_ids
  - Shows all books authored by this person
  - Automatically managed by Odoo ORM

## Constraints & Validations

### Essential Constraints
1. **Name validation**:
   ```python
   @api.constrains('name')
   def _check_name_not_empty(self):
       if not self.name or not self.name.strip():
           raise ValidationError("Author name is required")
   ```

2. **Date validation**:
   ```python
   @api.constrains('birth_date')
   def _check_birth_date_not_future(self):
       if self.birth_date and self.birth_date > fields.Date.today():
           raise ValidationError("Birth date cannot be in the future")
   
   @api.constrains('birth_date', 'death_date') 
   def _check_death_after_birth(self):
       if self.birth_date and self.death_date and self.death_date < self.birth_date:
           raise ValidationError("Death date must be after birth date")
   ```

3. **Name normalization**:
   ```python
   @api.model_create_multi
   def create(self, vals_list):
       for vals in vals_list:
           if 'name' in vals:
               vals['name'] = self._normalize_name(vals['name'])
       return super().create(vals_list)
   ```

## Implementation Notes

### Performance Considerations
- Index on `name` field for search performance
- Consider `stored=True` for `book_ids` if frequently accessed

### Duplicate Detection Strategy
- No enforced uniqueness constraint
- Future: implement duplicate detection wizard
- Future: add `is_duplicate` boolean field for manual merge workflows

## External IDs & Compatibility

### Stable External IDs
- Use pattern: `library_base.author_demo_cervantes`, `library_base.author_demo_shakespeare`
- Never change external IDs once published

### Backwards Compatibility Guarantees
- Field `name` remains required until major version bump
- Method `get_books()` signature will remain stable
- Field `partner_id` will remain optional
